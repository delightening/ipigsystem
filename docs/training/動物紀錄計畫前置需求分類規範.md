# 動物紀錄的「計畫前置需求」與「角色存取」分類規範

> **用途**：界定 (1) 哪些動物紀錄需要動物**已指派至已核准計畫（AUP）**才能建立；(2) 各**角色**對動物資料的**讀 / 寫**權限。
> **對象**：試驗人員、獸醫師、QA、系統維護者。
> **最後更新**：2026-06-15

---

## ⚠️ 現況 vs 目標規則（務必先讀）

本文件描述的是**目標 / 作業規範**。系統**現況**與目標不同，尚未完全依此強制：

| 維度 | 目標（本文件） | 系統現況 |
|---|---|---|
| **依紀錄類型** | 實驗性紀錄需已指派計畫；基礎照護紀錄免計畫 | **未依類型強制**，純權限一刀切 |
| **依角色讀寫** | 見下方「角色存取」表（PI / IACUC 唯讀、VET 限定、staff/admin/執行秘書可寫） | **view_all 角色（VET / IACUC / 審查委員）目前可寫入全部**；PI 對自己計畫的動物可寫 |

> 要真正落實，需後續程式碼變更（見文末 Follow-up）；在那之前本文件僅作教育與作業指引。

---

## 一、紀錄類型 → 計畫前置需求

| 紀錄類型 | 計畫前置需求 | 理由 |
|---|:---:|---|
| 手術紀錄 | **需已指派計畫** | AUP 管制的實驗性處置 |
| 犧牲 / 採樣 | **需已指派計畫** | 動物終點，AUP 管制 |
| 疼痛評估 | **需已指派計畫** | 實驗處置相關評估 |
| 病理組織報告 | **需已指派計畫** | 實驗結果 |
| 觀察紀錄（性質＝**試驗**） | **需已指派計畫** | 屬實驗操作 |
| 觀察紀錄（性質＝**異常 / 觀察**） | 免計畫 | 日常照護 / 異常監測 |
| 血液檢查 | 免計畫 | 健檢用途 |
| 體重 | 免計畫 | 基礎照護 |
| 疫苗 / 驅蟲 | 免計畫 | 基礎照護 |
| 基本資料 | 免計畫 | 進場建檔 |

**觀察紀錄細分**：依其「紀錄性質」欄位——**試驗**→需計畫；**異常 / 觀察**→免計畫。

## 二、角色存取（目標模型）

| 角色 | 對動物資料的存取 |
|---|---|
| **試驗人員**（試驗工作人員 / staff，`EXPERIMENT_STAFF`） | **可撰寫**：建立 / 編輯動物紀錄 |
| **系統管理員**（admin，`SYSTEM_ADMIN`） | **可撰寫** |
| **執行秘書**（IACUC 行政，`IACUC_STAFF`） | **可撰寫** |
| **獸醫師**（VET） | **限定撰寫**：獸醫建議／建議單、**巡場報告**（全流程＋照片）、轉讓的**獸醫健康評估**、安樂死建議單、各類 vet-read 已讀標記；其餘動物資料**唯讀** |
| **計畫主持人**（PI） | **唯讀**（所有動物資料） |
| **IACUC 委員 / 主席**（`REVIEWER` / `IACUC_CHAIR`） | **唯讀**（所有動物資料） |

> **讀取一律齊備**：上表「唯讀」= 對其**可存取**的動物，具備**全部讀取操作**（list 列表 / get 明細 / 下載附件 / 匯出 PDF·Excel）；讀取不再細分權限。可存取範圍：view_all 角色（IACUC / VET）＝全部動物；一般角色（PI / staff）＝其計畫關聯的動物。（讀取端點與寫入同走 `access::require_animal_access`。）

### 名詞對照
- **試驗人員 = 試驗工作人員 = staff**：實際執行實驗、輸入各項紀錄的人員（`EXPERIMENT_STAFF`）。
- **執行秘書 = IACUC 行政**（`IACUC_STAFF`）：IACUC 行政流程承辦。

### 與現況的差異（需 Follow-up 落實）
- **PI**：現況可寫入自己計畫的動物紀錄 → 目標改為**唯讀**。
- **IACUC 委員 / 主席**：現況為 view_all、可寫入全部 → 目標改為**唯讀**。
- **獸醫師**：現況為 view_all、可寫入全部 → 目標**限定**為獸醫建議／建議單、巡場報告、轉讓獸醫評估、安樂死單、vet-read 標記，其餘唯讀。
- 試驗人員 / admin / 執行秘書：維持可寫（與現況大致一致）。

## 三、設計理由

- 動物**進場、檢疫期**就應有基礎照護與健康紀錄（體重、健康觀察、疫苗驅蟲、血檢），不應因「尚未掛計畫」而無法記錄。
- **手術、犧牲採樣、疼痛評估、病理、試驗性觀察**是 AUP 核准範圍內的實驗處置，理應要求動物已指派至已核准計畫。
- **PI 與 IACUC 角色定位為審閱 / 監督**（唯讀），實際資料登錄由 staff / admin / 執行秘書負責，符合權責分離。
- **獸醫師**聚焦動物健康專業意見（建議）與動物福祉決策（安樂死），不負責一般實驗紀錄登錄。

## 四、Follow-up（不在目前文件範圍，需獨立評估與 PR）

若要讓系統**按本規範實際強制**，需要：

1. **紀錄類型檢查**：對「需計畫」紀錄（手術 / 犧牲採樣 / 疼痛 / 病理 / 試驗性觀察），於 service 層驗證動物 `iacuc_no` 非空，否則拒絕。
2. **角色讀寫控制**：
   - PI、IACUC 委員 / 主席 → 動物資料**唯讀**（移除其寫入路徑）。
   - 獸醫師 → 僅保留獸醫建議 + 安樂死單的寫入，其餘唯讀。
   - 確認 staff / admin / 執行秘書 的寫入路徑。
3. **放寬基礎紀錄權限**：讓可寫角色能對**未指派計畫**的動物建立「免計畫」紀錄。

> ⚠️ 以上同時涉及**收緊**（PI / IACUC / VET）與**放寬**（未指派動物的基礎紀錄）權限，屬資安敏感變更，須獨立 PR + 安全評估，對齊 `services/access.rs::require_animal_access` 與審計鏈。

## 附錄：動物管理「可撰寫操作」完整清單

> 來源：`backend/src/handlers/animal/*`（建立 / 編輯 / 刪除 / 提交 / 標記等寫入端點）。
>
> **讀取原則**：本清單只列「寫入」操作；**唯讀操作（list / get / 下載 / 匯出）不細分權限**——任何通過動物存取檢查（`access::require_animal_access`）的使用者，即具備該動物的全部唯讀操作。差異只在「**能否存取此動物**」與「**能否寫入**」兩個維度。

### A. 動物主檔
- 建立動物、編輯動物、刪除動物、批次指派計畫、vet-read 已讀標記

### B. 醫療紀錄
- 觀察：建立 / 編輯 / 刪除 / 複製 / 已讀標記
- 手術：建立 / 編輯 / 刪除 / 複製 / 已讀標記
- 體重：建立 / 編輯 / 刪除
- 疫苗・驅蟲：建立 / 編輯 / 刪除
- 血液檢查：建立 / 編輯 / 刪除 / 單項修正；血檢**模板・組合・預設**：建立 / 編輯 / 刪除
- 照護・疼痛評估：建立 / 編輯 / 刪除
- 病理組織報告：建立 / 更新（upsert）

### C. 終點與樣本
- 犧牲 / 採樣：建立 / 更新（upsert）
- 突然死亡：建立
- 廢棄物再利用樣本：建立（依動物／依安樂死）/ 編輯 / 刪除

### D. 轉讓（五關，皆為寫入）
- 發起 → 獸醫健康評估 → 指派接收計畫 → PI 核准 → 完成；另有駁回

### E. 獸醫專屬
- 獸醫建議：對觀察 / 手術新增建議（可含附件）
- 獸醫建議單（vet_advice）：建立 / 編輯 / 刪除
- 巡場報告：建立 / 編輯 / 刪除（草稿）、提交追蹤改善、確認收到、確認完成、報告級與條目級**照片**上傳 / 改說明 / 刪除
- vet-read 已讀標記（動物 / 觀察 / 手術）

### F. 行政 / 資料維護
- 動物欄位修正：提出修正申請、審核修正
- 匯入：基礎資料匯入、體重匯入
- 動物來源（基礎資料）：建立 / 編輯 / 刪除

> 跨模組關聯：**安樂死單**走獨立模組（`handlers/euthanasia.rs`），不在 `handlers/animal/` 下，但屬動物生命週期一環。
