# T23 ｜ 動物轉讓流程

> **受眾**：試驗人員、獸醫師（VET）　**建議時長**：30 分鐘　**前置**：已完成 T20 動物進場與建檔

## 學習目標

1. 依序說明動物轉讓的五個階段與各階段負責人。
2. 發起一筆轉讓並指派接收計畫。
3. 理解轉讓中的「資料隔離邊界」意義。

---

## 一、流程總覽

動物從一個計畫轉到另一個計畫，**不是單一步驟**，而是多階段把關，確保動物健康與資料權限正確交接。

| 階段 | 負責角色 | 動作 |
|------|----------|------|
| ① 發起轉讓 | 試驗人員 / PI | 選擇要轉出的動物、發起轉讓 |
| ② 獸醫健康評估 | 獸醫師（VET） | 評估動物健康狀況、核可或駁回 |
| ③ 指派接收計畫 | 試驗人員 / PI | 指定動物要轉入的目的計畫 |
| ④ PI 核准 | 接收計畫 PI | 接收方計畫主持人同意接收 |
| ⑤ 完成轉讓 | 系統 | 動物歸屬更新為接收計畫 |

---

## 二、操作步驟

### 2.1 發起轉讓（①）
- 在動物詳情或列表選擇動物、**發起轉讓**。

### 2.2 獸醫健康評估（②）
- 獸醫師檢視動物健康狀況，做出**核可**或**駁回**評估。駁回會退回，動物留在原計畫。

### 2.3 指派接收計畫（③）
- 通過評估後，**指派接收計畫**（動物要轉去的目的計畫）。

### 2.4 PI 核准（④）
- **接收計畫的 PI** 同意接收後，轉讓才能完成。

### 2.5 完成轉讓（⑤）
- 系統完成轉讓，動物歸屬更新為接收計畫。可於**轉讓紀錄**查看完整歷史。

### 2.6 資料隔離邊界
- 轉讓後，動物的歷史資料依**資料隔離邊界**規則管理：接收計畫看得到必要資訊，但不會無限制取得原計畫的所有機密資料。這是保護各計畫資料權限的設計。

---

## 三、注意事項

- ⚠️ 轉讓**必須經獸醫健康評估**，且須**接收計畫 PI 核准**，不能略過。
- ⚠️ 任一關被駁回，動物仍屬原計畫，需重新發起。
- 💡 留意資料隔離邊界，避免誤判可見資訊範圍。

## 📋 考題卷（可列印發給學員）

### 是非題（共 4 題）
1.（　）動物轉讓是單一步驟，發起後立即生效。
2.（　）轉讓過程中需由獸醫師進行健康評估。
3.（　）轉讓需經接收計畫 PI 核准才能完成。
4.（　）轉讓完成後，接收計畫可無限制取得原計畫的所有機密資料。

### 選擇題（共 4 題）
5. 動物轉讓的正確階段順序是？
   - (A) 獸醫評估 → 發起 → 完成
   - (B) 發起 → 獸醫健康評估 → 指派接收計畫 → PI 核准 → 完成
   - (C) 完成 → 發起 → 評估
   - (D) 發起 → 完成 → 評估
6. 轉讓過程中誰負責「健康評估」？
   - (A) 倉庫管理員　(B) 獸醫師（VET）　(C) IACUC 主席　(D) HR
7. 轉讓要能完成，除獸醫評估外還需誰同意？
   - (A) 接收計畫的 PI　(B) 外部客戶　(C) 系統自動　(D) 不需任何人
8. 「資料隔離邊界」的主要目的是？
   - (A) 加快轉讓速度
   - (B) 保護各計畫資料權限，限制可見範圍
   - (C) 自動刪除動物紀錄
   - (D) 產生庫存報表

## ✅ 標準答案與解析（講師用）

| 題號 | 答案 | 解析 |
|------|------|------|
| 1 | ✗ | 轉讓為多階段（5 關）流程，非單一步驟。 |
| 2 | ✓ | 第二關為獸醫健康評估。 |
| 3 | ✓ | 需接收計畫 PI 核准。 |
| 4 | ✗ | 受資料隔離邊界限制，非無限制取得。 |
| 5 | **B** | 發起→獸醫評估→指派計畫→PI 核准→完成。 |
| 6 | **B** | 獸醫師負責健康評估。 |
| 7 | **A** | 接收計畫 PI 核准。 |
| 8 | **B** | 保護各計畫資料權限、限制可見範圍。 |
