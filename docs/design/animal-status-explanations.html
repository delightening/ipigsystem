一、核心對比：實驗完成 vs 已安樂死

實驗完成

🟢 做完實驗，但動物還活著
  • 仍在場內、仍可登錄體重
  • 非終點：後續還要「轉讓」或「安樂死」處置
  • 徽章：綠色（success）

已安樂死

🔴 已執行安樂死／犧牲，動物已死亡
  • 終點狀態，不可再變更
  • 不可再登錄體重等就地操作
  • 徽章：紅色（error）

一句話：「實驗完成」＝做完但還活著；「已安樂死」＝已經死亡。兩者最常被混為一談，是這次補說明的主因。

四、三個混淆點各自怎麼被處理

混淆這次怎麼處理
a 以為「實驗完成」＝死亡 每個彈窗最上方標「存活 / 已死亡」一眼判讀；「實驗完成」彈窗加 ⚠️ 明說「不等於動物已死亡」。
b 不知道完成後要做什麼 每個狀態都有「後續」一行，寫清楚可轉去哪些狀態（轉讓 / 安樂死…）。
c 「已犧牲」位置 vs「已安樂死」狀態看似矛盾 成因：列表位置欄在 completed 且無欄位時顯示「已犧牲」（constants.ts:71），但狀態仍是「實驗完成」。
處理：彈窗點明「動物生死以『狀態』欄為準；位置顯示『已犧牲』僅代表已離開原欄位」。
需你裁決：(c) 是否更進一步改該位置文案（例如離欄改顯示「已離欄 / —」而非「已犧牲」）？這屬 code 語意調整，建議另議、非本次 UI 說明範圍。

五、未來方向（已定調 · 非本次施作）

關於「離場」，經討論後的結論：

  • 目前只有院內 internal 轉讓（計劃間互轉），動物一律在場內；external（轉出院外）歷史上從未發生、目前純假設無時程。
  • 單一場地為主、無多院區規劃 → 不採「在場/離場」正交維度（方案 B 屬過度設計，擱置）。
  • 未來 external 真要用時：新增專屬「已轉出院外」終態（方案 A），比照「已安樂死／猝死」為終點，不再退回顯示「實驗中」。屆時屬 schema／狀態機改動，會先出設計提案再動 code。
