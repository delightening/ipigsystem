犧牲 / 安樂死 / byproduct 採樣 — 流程示意圖

依現行程式碼繪製（2026-06-07）。兩條路徑都會產生「犧牲紀錄 + 動物=euthanized」，但只有路徑 A 有安樂死單 id。
路徑 A：安樂死單工作流（euthanasia_orders） 路徑 B：直接犧牲表單（animal_sacrifices） 共同結果 byproduct 採樣的缺口
動物（status：unassigned / in_experiment / completed） 實驗結束、需結束動物生命時
▼ 兩種做法 ▼

路徑 A — 安樂死單（正式審批流）

表：euthanasia_orders（0..N / 動物）
Vet 開單status = pending_pi · 設 deadline（PI 24h 內回應）
↓
PI 同意 → approvedPI 簽章；或 PI 申訴 → appealed → Chair 仲裁
↓
Vet 執行 → executed執行簽章（不可逆）
↓
execute() 同 tx 自動： • order → executed
• INSERT animal_sacrifices（帶執行時填的方法細節）
• animals.status → euthanized

路徑 B — 直接犧牲表單（SacrificeTab）

表：animal_sacrifices（1:1 / 動物）
Vet 在動物頁填「犧牲/採樣」表單Zoletil 劑量、電擊、放血、採血量…
↓
勾「確定犧牲」 confirmed_sacrifice = trueupsert_sacrifice（medical.rs:278）
↓
同 tx 自動： • INSERT/UPDATE animal_sacrifices（ON CONFLICT animal_id）
• animals.status → euthanized
• 不需任何安樂死單
（沒有 euthanasia_orders 紀錄）
▼ 兩路徑匯流 ▼
共同結果：animal_sacrifices 紀錄存在　+　animals.status = euthanized
犧牲紀錄可被 GLP 鎖定（is_locked）成不可變醫療紀錄
