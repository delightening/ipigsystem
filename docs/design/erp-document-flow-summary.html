採購單 / 採購入庫的串接、庫存如何變動、以及本次稽核「各項目顯示是否正確」的結論 · 2026-07-18

一句話：單據是「決策紀錄」，庫存是「事實帳」。單據核准（approved）那一刻才真正動到庫存與會計； 草稿/送審中的單據只是計畫，不影響任何數字。你遇到的 PO-260422-01「已核准未入庫」正是這個原理 —— 它的入庫單還是草稿。

1 · 單據怎麼流動

採購單 PO跟供應商下單。不動庫存，只記「要進多少」。
→
採購入庫 GRN貨到了收貨。核准後庫存 +、寫會計傳票。用 source_doc_id 指回 PO。
→
庫存帳stock_ledger（倉庫層流水）＋storage_location_inventory（貨架層）。

反向出貨為 SO 一段式（2026-07 起）：SO 銷貨單核准 → 逐行照儲位所屬倉 庫存 −、寫會計傳票； 同一張 SO 可跨多倉出貨（明細層級倉庫）。舊制 DO 銷貨出庫 已棄用，僅保留舊單查詢。其餘還有調撥、盤點、調整、退貨等。

「軟擋」= 建議填但缺了不擋，核准後列入「未上架待辦」；缺儲位的 GRN 核准會使倉庫總量上升、但貨架層是「未分配」（見 §4）。

3 · 狀態流：什麼時候才「當真」

draft 草稿隨便改、隨便刪。不影響任何數字。
→
submitted 送審等核准。仍未動帳。
→
approved 核准此刻才寫庫存 + 會計傳票。
／
cancelled 作廢

關鍵：採購單的「入庫進度」receipt_status 只統計已核准（approved）的 GRN。草稿 GRN 一律不算 —— 這是設計上正確的，避免「還沒真的收貨就顯示已入庫」。

4 · PO ↔ GRN 串接與「入庫進度」三態

系統把某張 PO 底下所有已核准 GRN 的數量加總（total_received），跟 PO 訂購量（total_ordered）比較：

條件receipt_status畫面顯示
total_received == 0pending未入庫
0 < received < orderedpartial部分入庫
received ≥ orderedcomplete已入庫

實例：PO-260422-01（斯特普科技）

狀態
approved（已核准）
掛的 GRN
2 張 —— GRN-260717-01、GRN-260718-01，都還是草稿（draft）
已核准入庫量
0（草稿不算）→ receipt_status = pending
畫面
已核准未入庫 ← 顯示正確，不是 bug

要真正入庫怎麼做：把其中一張 GRN 核准（草稿→approved），系統就會寫庫存、把 PO 更新為已入庫。兩張是重複建立，另一張刪掉即可。

6 · 新增的刪除安全規則（PR #985）

  • 連動刪草稿下游：刪 PO 會把它掛的草稿 GRN 一起刪（掃描整條下游鏈，各自寫 audit）。
  • 擋已核准下游：下游有任何非草稿單據 → 擋下並列出單號，不默默移除。
  • 硬擋 已寫庫存/會計的單據絕不可刪：只要有 stock_ledger 或 journal_entries（例如已核准並入庫的 GRN），一律擋刪 —— 避免孤兒化庫存/帳。
  • 權限：硬刪已核准單據僅限 admin；每筆刪除都寫 DOC_HARD_DELETE / DOC_DELETE 稽核紀錄。
