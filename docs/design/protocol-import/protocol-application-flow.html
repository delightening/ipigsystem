② 落差總表（系統 vs 實際流程）

環節狀態系統現況改善方向
申請須知 + 須知簽名 缺口 完全無：無須知文件版本管理、無申請人同意簽署、submit 不檢查 本次實作（已裁定）：全院共用「須知版本表」（版次制）+ 申請人手寫電子簽章（複用 signature_bridge）+ submit 前驗證已簽當前生效版本
收件證明 部分 SUBMITTED 自動生 APIG 編號，但不產出「收件證明」文件 可選：收件時產出收件證明 PDF（後續評估）
執行期間：教育訓練 / 人員新增 部分 人員/動物模組 + amendment，但與「教育訓練紀錄」「臨時名單」對應度待確認 盤點覆蓋度（後續）
結案報告 部分 CLOSED 狀態存在，但無結構化結案報告文件產出/上傳 可選：結案報告附件 / 範本（後續）
審查里程碑時間軸 對應 import-approved 已支援 backfill：申請→預審→獸醫→委員一審→補件→委員二審→核准 —
委員意見 + 申請人回覆 對應 import-reviews 支援院外審查者姓名 + reply + section_no —（收件證明裡的審查過程可灌入此處）

③ 舊計劃匯入路徑（歸檔資料夾 → 系統）

0. 取版 — 每個 PIG 資料夾挑出「核准前最後一版申請表」 去除 ~$ 暫存鎖檔 / Thumbs.db；多日期版本取最新（如 1230 > 1209） 來源：1-申請表\ 最新版 + 9-附件
▼
1. import-approved — 建立 APPROVED + import_pending 計劃 title / iacuc_no(PIG-xxx) / application_no(APIG-xxx) / PI / SD / 起迄日 + 7 個審查里程碑日期 POST /api/v1/protocols/import-approved
▼
2. 補登內容 — import_pending 期間直接編輯 working_content 把申請表抓出的 PI / 動物數 / 設計方法等填入 PUT /api/v1/protocols/{id}
▼
3. import-reviews — 補登審查意見（收件證明的審查過程） 執秘意見 / 委員一審二審意見 + 申請人回覆 / 獸醫評比 POST /api/v1/protocols/{id}/import-reviews
▼
4. finalize-import — 建 v1 版本快照 + 清 import_pending 原計劃書版本號（如 v2.1） POST /api/v1/protocols/{id}/finalize-import
⚠️ 匯入時的須知簽名缺口：步驟 0–4 不包含「申請須知簽名」（2-申請須知簽名檔），因系統目前無處可放。 本次將先補上須知功能（落差表第 1 列），匯入流程才能完整承接歸檔內容。流程圖確認後進入實作。
