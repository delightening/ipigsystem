計畫書「版本名冊（manifest）」補登流程

方案 (Y)：單一超集資料 + 每版一張名冊 · 2026-07-09 設計對齊 · 先不動 code

階段一　一次性建置版本名冊（manifest）

盤點各版本欄位C(=D) · E · F　實際 3 種結構（C 案 D 案皆印 AD-04-01-01C）
↓
定義「超集」所有版本欄位的聯集，含 F 已砍掉的孤兒欄位
↓
為每版建一張名冊名冊 = 共同核心 ∪ 該版專屬欄位（宣告式清單，非程式）
↓
登記到計劃書範本版本頁protocol_template_versions：登記版本、供補登「選版本」下拉帶出
名冊建好後 ↓ 才進補登

階段二　逐筆補登（可編輯）

開補登新案 / 已補登舊案已補登者：重新選版本，回填 source_form_version
↓
先選版本依你已知的「案子 → 版本」對照手動選（不自動偵測）
↓
系統依該版名冊只渲染該版欄位F 獨有欄不顯示；孤兒欄位歸該版顯示
↓
補登 / 編輯資料編輯限定在該版名冊欄位範圍內
↓
finalize-import
落地後 ↓ 進入日常

階段三　下游與日後

共同核心欄位（每版都有）→ 會計項目 / 豬隻使用數量：不受版本影響，安全
變更申請可選：沿用原版　或　升級最新版（預設建議升級）；最新版動態解析 F→G/H/I/J/K
◆ 決策節點（手動選版本 / 變更升級） 版本可持續擴充：F 之後 G/H/I/J/K，「最新版」動態解析

實際只有 3 種結構：C 案/D 案皆印 AD-04-01-01C、E、F → 名冊只需 3 張（C/D 共用）。 版本演化非單調：C/D→E 加 SD/PI 分離·委託聯絡人·替代 3 平台，減 試驗單位塊·GLP 結果分析·文件歸檔·飼養 SOP·試驗物質 11→5 欄·簽核 3→2 列； E→F 加 替代 8 平台·痛苦症狀 17·緩解措施 4·資料庫 A~L·減量細分·精緻化·PI 職稱·類型 6·重複 4 選項，減 試驗物質類型 9·技術類別 9·註冊機關 5。 採 (Y) 後結構性「不適用」不需要——該版沒有的欄位直接不顯示。共同核心每版都含，保護下游會計與豬隻計數。完整記錄見同資料夾 version-manifest-backfill-plan.md。
