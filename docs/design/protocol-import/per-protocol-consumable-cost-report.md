# 設計討論：以計劃為單位的耗材耗用 + 成本 + 庫存剩餘 報表

> 草稿（討論用）｜2026-06-08 ｜ 來源：#56 reframe — 研究單位無銷售訂價/無毛利概念，只要看「成本」。

## 1. 目標（使用者描述）

以**計劃（protocol）為單位**，了解三件事：
1. **耗用多少耗材**（數量）
2. **成本**（＝進貨單價 × 耗用量；不算毛利、不算加權平均）
3. **倉庫裡還有多少量、值多少錢**（全倉 + 以計劃預留，兩者都要）

## 2. 現有資料模型盤點（已勘查 current main）

| 要素 | 現況 | 位置 |
|---|---|---|
| 出庫單綁計劃 | ✅ `documents.protocol_id Option<Uuid>`；**DO（銷貨出庫）** 是耗材發出 | `models/document.rs:133` |
| 出庫明細 | ✅ `document_lines.qty` + `unit_price`（Decimal） | `models/document.rs:156/158` |
| 產品成本 | ✅ `products.cost_price Option<Decimal>`（進貨/成本價） | `models/product.rs:65` |
| 倉庫現有量 | ✅ `storage_location_inventory.on_hand_qty`（per 倉位×品項） | `models/storage_location.rs:141` |
| 庫存「金額」 | ⚠️ 現有「庫存價值」用 **selling_price**（售價）算 → 你要的是**成本**，需改 cost_price | `models/warehouse.rs:91` |
| 以計劃預留庫存 | ❌ **不存在**——庫存無 protocol 欄、無 reserved 欄，stock 是共用的 | — |

**單據類型**（`DocType`）：PO 採購單 / **GRN 採購入庫** / PR 採購退貨 / SO 銷貨單 / **DO 銷貨出庫** / TR 調撥 / STK 盤點 / ADJ 調整 / SR 銷貨退貨 / RTN 退貨。

## 3. 三項需求 — 可行性與做法

### (1) 耗用量 + (2) 成本 — ✅ 現有資料即可做，無需新計算
- **耗用量** per 計劃 = 對 `DO`（且 `status=approved`、`protocol_id=X`）的明細 `SUM(qty)`，依 product 分組。
- **成本** = `SUM(qty × 成本單價)`。成本單價來源**待你選**（見 §5 Q-B）：
  - (a) `products.cost_price`（主檔成本價）— 最簡單、一致。
  - (b) DO 出庫明細的 `unit_price`（出庫當下記的價）。
  - (c) GRN 進貨均價 — 較準但要查 + 算平均（偏「複雜」，不建議）。
- **不需加權平均**（用單一成本基準 × 量即可），符合「不要複雜計算」。

### (3a) 倉庫剩餘「全倉」量 + 金額 — ✅ 可做，只需把金額基準從售價改成本
- 量 = `SUM(on_hand_qty)` per product（跨倉位）。
- 值 = `SUM(on_hand_qty × products.cost_price)`（把現有 `warehouse.rs:91` 的 selling_price 改 cost_price，或另出一個「成本口徑」庫存值）。

### (3b) 倉庫剩餘「以計劃預留」量 + 金額 — ⚠️ 目前模型做不到，需先定義
- 系統**沒有「計劃預留/配額庫存」概念**（庫存是全倉共用、不綁計劃）。要做有兩條路：
  - **路 A（衍生餘額，不改庫存模型，推薦）**：以「為某計劃採購/配給的量 − 該計劃已耗用量」推算「該計劃名下還剩多少」。不是物理鎖庫存，而是帳面餘額。需定義「為計劃採購」怎麼認（PO/GRN 是否綁 protocol？目前 GRN 由 PO 自動產，PO 有 protocol_id 則可追）。
  - **路 B（物理預留，新功能，較大）**：新增「庫存配額/預留」資料表，領用前先對計劃配額，剩餘 = 配額 − 已領。這是一個獨立的庫存配額管理功能（schema + 流程 + UI）。
- **這題是本設計最大的未決點**（見 §5 Q-A）。

## 4. 建議方案（草案）

一張新報表頁「**計劃耗材成本**」，兩個區塊：

- **區塊 A：各計劃耗用明細**（核心，現有資料即可）
  | 計劃 | 品項 | 耗用量 | 成本單價 | 成本小計 |
  - 可依計劃彙總 + 展開品項；可選日期區間；可匯出 Excel。
- **區塊 B：倉庫剩餘（成本口徑）**
  - 全倉：品項 × 現有量 × 成本 = 庫存成本值（總覽）。
  - 以計劃剩餘：**依 §5 Q-A 的決定**再定（路 A 衍生 or 路 B 物理預留 or 暫不做）。

**與現有報表（#56）的關係**：現有「進銷貨彙總 / 損益表」的「毛利/損益」對研究單位不適用 → **移除毛利欄、改純金額/成本**（你已確認）。本新報表上線後，舊損益分頁可考慮退役。

**成本基準一律用「進貨/成本價」**，不做加權平均移動成本。

## 5. 決議（2026-06-08 討論定案）

- **A-A「以計劃庫存剩餘」= 衍生餘額（路 A）**：剩餘 = 為計劃採購量 − 已耗用量。**不改庫存模型、零 schema 變更**。
  - 為計劃採購量 = 綁該 `protocol_id` 的入庫（GRN，approved）明細 `SUM(qty)`。
  - 已耗用量 = 綁該 `protocol_id` 的出庫（DO，approved）明細 `SUM(qty)`。
- **A-B 成本單價 = `products.cost_price`（主檔成本價）**。成本 = 量 × cost_price，不做加權平均。（前提：cost_price 需有維護；缺值時報表標示「成本未設定」。）
- **A-C `DO` 全算耗用**：所有綁計劃的 approved DO 出庫＝該計劃領用耗材，全部計入。
- **A-D 退貨沖回（預設，未特別討論）**：採**淨額**——耗用淨額 = DO − 對應 SR/RTN（銷貨退回入庫）；採購淨額 = GRN − PR（採購退貨）。若你要「只看毛出庫不扣退回」再改。

→ **結論：三項需求皆可用現有資料表達，無需 migration。** cost_price 缺值是唯一資料品質前提。

## 6. 實作分期（暫定，待 §5 定案）

- **Phase 0**：#56 清理——移除現有進銷貨/損益報表的毛利欄（小，併修復批次）。
- **Phase 1**：各計劃耗用 + 成本明細 報表（API + 頁面 + 匯出）。現有資料即可，無 schema 變更。
- **Phase 2**：全倉剩餘（成本口徑）。小，改金額基準。
- **Phase 3**：per-計劃剩餘——依 Q-A 決定（路 A 衍生 = 中；路 B 物理預留 = 大、需 migration）。
