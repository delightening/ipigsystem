排版規則說明 + 取捨

共同基礎：在 N 欄網格上掃描，由上而下、由左而右，把每個 widget 放進「放得下、且 y 最小、其次 x 最小」的位置，不重疊。窄螢幕（9/6 欄）時寬度夾到欄數內。差別只在「餵進去的順序」。

  • A 預設順序（保序 + 垂直壓實）：依 DEFAULT_DASHBOARD_LAYOUT 的邏輯分組順序打包。等同 react-grid-layout 的 vertical compact。優點：分組語意清楚（快捷列在最上、ERP 警示成群）。缺點：可能留下右側／中間小空洞。
  • B 面積大→小（FFD）：先放大塊，小塊填縫。優點：通常最緊密、空洞最少。缺點：語意順序被打散（Google 日曆這種大塊會被推到最前）。
  • C 列優先（shelf）：一列填滿才換下一列，列高取該列最高者。優點：行列最整齊、可預期。缺點：右緣與列間易留空，填充率最低。
  • D 高度高→矮（FFDH）：高的先放，矮的補。介於 A 與 B 之間，視覺較平衡。

關於「顯示/隱藏」如何處理（你問的），三種語意，建議用第 1 種：

  1. 完全重設（推薦）：恢復「預設顯示/隱藏」+ 重新最佳化排版。最符合「重設」二字的直覺，一鍵回到乾淨初始狀態。
  2. 保留顯示選擇，只重排：尊重你目前開/關了哪些 widget，只把「目前顯示中」的重新打包。比較像「整理」而非「重設」。
  3. 顯示全部 + 重排：把所有有權限的 widget 都打開再排。通常太擠，不建議當預設。

若想兩者都要，可考慮把按鈕拆成「重設佈局」（語意 1）與「整理排版」（語意 2）兩顆。
